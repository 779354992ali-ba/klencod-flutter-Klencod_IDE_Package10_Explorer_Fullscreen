# Package62 — مستودع النسخ الاحتياطية

## مكان التخزين

عند إنشاء نسخة احتياطية لمشروع مفتوح، يحفظ التطبيق نقطة استعادة إضافية داخل:

- `.bisho-backups/catalog.json` — فهرس JSON بإصدار schema مستقل.
- `.bisho-backups/snap_<timestamp>.json` — محتوى النسخة الاحتياطية الكامل.

يتم إنشاء الملفات والمجلدات وقراءتها وحذفها عبر `SafFileService` وواجهات Storage Access Framework، وتبقى هذه البيانات ضمن مجلد المشروع الذي اختاره المستخدم.

## إدارة نقاط الاستعادة

افتح لوحة الأدوات ثم اختر **سجل النسخ**. يعرض السجل أحدث النقاط أولًا مع التاريخ وعدد الملفات والمجلدات والحجم. يمكن استعادة نقطة بعينها أو حذفها بعد تأكيد المستخدم. الحد الأقصى 20 نقطة؛ عند تجاوز الحد، تُكتب النقطة الجديدة والفهرس المحدّث أولًا ثم تزال النقاط الأقدم.

الاستعادة تتحقق من بصمة ملف النسخة ثم تمرر محتواه إلى `ProjectBackupService.decode` للتحقق من البنية والمسارات وبصمات الملفات. بعدها تنشئ مجلدًا جديدًا ولا تكتب فوق مشروع موجود. وإذا فشلت الكتابة، يحاول التطبيق تنظيف مجلد الاستعادة الجزئي.

## المقارنة

من سجل النسخ اختر **مقارنة نسختين**، ثم حدد النسخة الأقدم والأحدث. تقرأ الأداة النسختين وتتحقق من سلامتهما قبل المقارنة، ثم تعرض الملفات المضافة والمحذوفة والمعدلة والثابتة. المقارنة على مستوى الملفات وبصماتها، وليست مقارنة سطرية لمحتوى كل ملف.

## السلامة والحدود

- مجلد `.bisho-backups` مستثنى من النسخ المتكررة حتى لا تنسخ النسخ الاحتياطية نفسها داخل كل نقطة جديدة.
- أسماء ملفات النقاط مولّدة داخليًا ومقيّدة بنمط آمن؛ لا تُقبل أسماء مسارات يحددها ملف الفهرس.
- حذف النقطة يحدث بعد تحديث الفهرس، لتقليل احتمال فقد نقطة ما زالت مشارًا إليها.
- إذا فشل حفظ الفهرس بعد كتابة ملف نسخة جديد، قد يبقى ملف يتيم غير ظاهر في السجل؛ لا يُحذف أي سجل قديم في هذه الحالة.
- البصمة FNV-1a 32-bit تكشف التلف العرضي فقط، ولا توفر توقيعًا تشفيريًا أو حماية ضد التلاعب المتعمد.
- يظل التصدير المحمول إلى ملف JSON متاحًا كما في Package61.
