# Bisho IDE Package 38 — One-Build Readiness

## Changes
- Fixed generated Flutter `lib/main.dart`: it no longer imports an internal Bisho IDE service that does not exist in a newly generated project.
- Every newly created Flutter project now receives `.github/workflows/build-android.yml`.
- The generated workflow uses the official Flutter CLI (`flutter create --platforms=android .`) to create the Android platform at build time, adds Android INTERNET permission, fetches dependencies, analyzes, tests, builds a release APK, and uploads the APK artifact.
- Added ZIP import path validation and archive size/count limits before creating the destination project folder.
- Added unit tests for ZIP path traversal and archive size/count validation.
- Bumped package version to 1.0.0+38.

## Important behavior
- Android Gradle platform files are generated by Flutter in GitHub Actions, not fabricated in the phone editor. This is deliberate: Flutter's official template supplies the matching Gradle wrapper, plugin configuration, Kotlin activity, manifest, and resources for the installed Flutter version.
- A newly created Flutter project is immediately ready to push to GitHub. In its repository, open Actions and run `Build Android APK` (or push to main/master). The APK is uploaded as a workflow artifact.

## Validation
- Source-level checks and ZIP structure review performed in the packaging environment.
- Flutter SDK/Dart CLI are not installed in this packaging environment, so `flutter analyze`, `flutter test`, and APK build are not claimed as passed. The repository workflow runs analyze, tests, and build in CI.
